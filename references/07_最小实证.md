# 世界分析法阶段冻结07｜最小实证 v1.0

> **状态：阶段冻结**  
> **所属 Skill：** 世界分析法（world-analysis）  
> **作用：** 作为后续世界分析法 Skill 的正式设计事实源之一。

---

## 1. 定义

> **最小实证：围绕明确决策与竞争假设，识别真正具有区分力且足以改变决策的证据，在保留关键现实条件和必要变量交互的前提下，设计成本最低的决策充分实验，并以真实观测决定、缩小或重新设计当前判断。**

它回答的核心问题是：

> **最低成本做什么，才能让我们真正知道，并足以推动当前决策？**

---

## 2. 核心原则

最小实证中的“最小”正式定义为：

> **Minimum Decision-Sufficient Experiment｜最小决策充分实验**

它不是：

- 样本最少；
- 代码最少；
- 成本绝对最低；
- 最快做出一个 Demo。

而是：

> **在满足当前决策所需真实性与区分力的前提下，尽可能降低实验成本。**

因此：

```text
Minimum
≠
Toy
```

更准确地说：

```text
Minimum
=
保留决定结论的关键现实条件
+
删除不会影响当前决策的非必要实验结构
```

---

## 3. 适用场景

优先用于：

- 双向钢人得到 `Insufficient Evidence`；
- 外部证据校核得到 `Inconclusive`；
- 两个方案理论上都成立，但真实收益未知；
- 性能、成本、稳定性、用户效果等必须通过真实数据判断；
- 某项能力是否值得引入额外复杂度尚不确定；
- 实验性假设需要进入真实验证；
- 需要判断某项机制是否值得产品化；
- 外部成熟实践无法直接决定当前场景时。

通常不用于：

- 可以直接通过事实查询解决的问题；
- 已存在决定性实证的问题；
- 仅为了展示“技术能跑起来”的 Demo；
- 无明确决策问题的随意试验。

---

## 4. 最小输入

```text
Decision Question
到底需要决定什么？

Competing Hypotheses
当前有哪些竞争假设？

Decision Variable
什么结果真正会改变当前决策？

Decision Threshold
结果至少达到什么程度，才足以改变决策？

Constraints
实验允许投入多少成本、时间和风险？

Success / Failure Meaning
什么结果支持、削弱或无法区分竞争假设？
```

其中最重要的是：

```text
Decision Question
Decision Variable
Decision Threshold
```

原则：

> **如果实验结果无论怎样都不会改变当前决策，这个实验就不值得做。**

---

## 5. 核心流程

最小实证正式冻结为：

```text
Define Decision
↓
Form Competing Hypotheses
↓
Identify Discriminating Evidence
↓
Define Decision Threshold
↓
Design Minimum Decision-Sufficient Experiment
↓
Reality Fit Test
↓
Run
↓
Interpret
↓
Decide / Redesign
```

---

## 6. Define Decision｜先定义决策

实验必须先回答：

> **到底需要做什么决策？**

不要从：

> “测试一下 Graph DB。”

开始。

而应该表达为：

> “在当前 Memory Query Pattern 下，Graph DB 带来的收益是否足以覆盖新增基础设施复杂度？”

原则：

> **实验服务于决策，而不是为了产生数据。**

---

## 7. Form Competing Hypotheses｜形成竞争假设

实验必须至少存在两个能够被结果区分的解释或方案。

例如：

```text
H1
Graph DB 在当前高关系密度、多跳查询场景下
能够产生足以覆盖额外成本的收益

H2
PostgreSQL 已能满足当前需求
Graph DB 的新增收益不足以改变架构
```

竞争假设可以是：

- 单变量假设；
- 方案级假设；
- 组合假设。

正式冻结：

> **复杂系统中允许验证 Composite Hypothesis｜组合假设。**

不要求所有实验都只改变一个变量。

---

## 8. Identify Discriminating Evidence｜识别区分性证据

问：

> **什么真实观测能够真正区分竞争假设？**

例如：

```text
两个系统都能运行
```

通常没有区分力。

真正有价值的证据可能是：

```text
Latency
Error Rate
Task Success
Recovery Cost
Token Usage
Operational Cost
Implementation Complexity
User Outcome
```

原则：

> **实验不是收集尽可能多的数据，而是收集足以区分当前竞争假设的数据。**

---

## 9. Define Decision Threshold｜定义决策阈值

发现差异，不等于差异足以改变决策。

例如：

```text
方案 B 快 3%
```

可能技术上存在优势，但不足以承担：

```text
新增数据库
新增运维
迁移成本
治理成本
```

因此实验前应明确：

> **结果达到什么程度，才值得改变当前方案？**

Threshold 可以来自：

- 业务目标；
- SLA；
- 产品承诺；
- 当前 Baseline；
- 成本约束；
- 用户明确要求；
- 已冻结策略。

正式禁止：

> **Agent 为了完成实验设计而自行编造 Decision Threshold。**

如果无法合理定义阈值，应将其保留为：

> **未决决策变量**

而不是制造伪精确数值。

---

## 10. Design Minimum Decision-Sufficient Experiment｜设计最小决策充分实验

实验设计目标：

> **只保留足以产生决策级证据的最小真实条件。**

例如验证 Graph DB，不需要建设完整 Memory Platform。

可能只需要：

```text
代表性数据集
+
真实 Query Set
+
两个最小实现
+
统一测试条件
```

前提是这些条件已经足以支持当前架构决策。

---

## 11. Reality Fit Test｜现实适配检查

在执行前必须检查：

> **当前实验是否保留了真正决定生产结果的关键现实条件？**

重点检查：

- 代表性输入；
- 代表性规模；
- 真实 Workload；
- 关键约束；
- 关键失败模式；
- 必要变量交互；
- 决策相关成本；
- 决策相关质量指标。

原则：

> **删掉某个现实条件后，如果它可能改变最终决策，就不能删。**

Reality Fit 不要求完整复制生产环境。

要求的是：

> **Minimum Decision-Relevant Reality｜最低决策相关真实性。**

---

## 12. 变量隔离原则

最小实证优先：

> **隔离主要不确定性。**

原因：

> 如果一次同时改变太多无关变量，就无法解释结果为什么变化。

但正式冻结：

> **变量隔离不是绝对规则。**

如果关键变量存在不可消除的真实交互：

```text
Variable A
×
Variable B
×
Variable C
```

且这种交互本身决定结果，则应：

> **保留必要交互，并明确当前验证的是组合假设。**

因此：

```text
能隔离
→ isolate

无法隔离且交互决定结果
→ test interaction
```

不得为了形式上的控制变量破坏真实机制。

---

## 13. Minimum ≠ Demo

一个实验可能很小，但必须能够支持真实决策。

例如验证 Agent Runtime Checkpoint：

错误实验：

```text
sleep 30 秒
↓
kill process
↓
resume
```

它最多只能证明：

> checkpoint 技术能够运行。

却无法回答：

> checkpoint 是否值得成为产品能力。

决策充分实验可能还必须保留：

```text
真实任务结构
真实 Intermediate State
Restart Cost
Resume Cost
恢复正确性
关键 Failure Point
必要 Effect Safety
```

原则：

> **技术可行性证明不等于产品价值证明。**

---

## 14. Run｜执行实验

执行时必须尽量保证：

- 输入条件可比较；
- 关键变量变化可解释；
- 测量方式一致；
- 结果可重复或至少可审查；
- 失败与异常被记录；
- 不因看到中间结果随意修改评判标准。

如果实验执行中发生重大条件变化：

> 应记录并重新判断实验是否仍具有 Decision Sufficiency。

---

## 15. Interpret｜解释结果

正式允许四类 Verdict：

```text
Supports Focal
Supports Rival
Conditional
Non-discriminating
```

---

### 15.1 Supports Focal

真实结果达到 Decision Threshold，并明显支持当前主张。

---

### 15.2 Supports Rival

真实结果支持竞争方案，或当前主张的收益不足以改变决策。

---

### 15.3 Conditional

结果表明真正决定结论的是某个条件变量。

例如：

```text
高关系密度 + 高频多跳查询
→ Graph DB 有明显价值

普通查询
→ PostgreSQL 足够
```

此时应把原方案判断重构为：

> **条件性结论。**

---

### 15.4 Non-discriminating

实验没有产生足够区分性证据。

注意：

```text
Non-discriminating
≠
两个方案一样
```

它可能意味着：

```text
真实差异确实很小
```

也可能意味着：

```text
实验设计没有测到关键差异
```

因此需要进一步判断：

> 是停止，还是重新设计实验。

---

## 16. Decide / Redesign｜决策或重新设计

实验结束后必须明确：

```text
Evidence sufficient
→ Decide

Evidence insufficient because test design weak
→ Redesign Experiment

Evidence reveals new condition
→ Reframe Hypothesis

Evidence reveals new unknown
→ Return to Analysis
```

不得为了“实验已经做了”而强行形成结论。

---

## 17. 与外部证据校核的边界

```text
外部证据校核
→ 别人的世界发生了什么？
```

```text
最小实证
→ 在我们的世界里实际会发生什么？
```

外部证据可以帮助：

- 形成假设；
- 选择实验方式；
- 识别关键指标；
- 判断值得测什么。

但不能替代：

> **当前项目自身的真实观测。**

---

## 18. 与双向钢人的边界

双向钢人用于：

> 比较两个最强竞争解释。

当双方都合理，但关键变量缺少事实时：

```text
Insufficient Evidence
↓
最小实证
```

因此：

> **双向钢人负责发现决定变量，最小实证负责测量这些变量。**

---

## 19. 与不变量与极端反例的边界

不变量与极端反例：

```text
→ 通过逻辑与场景主动尝试证伪
```

最小实证：

```text
→ 通过真实执行与观测获得证据
```

如果某个 Failure Mechanism 只能通过真实运行确认：

> 可使用故障注入、回放或真实实验进入最小实证。

---

## 20. 停止条件

正式停止条件：

> **已经获得足以达到或否定当前 Decision Threshold 的区分性证据，或者已经确认当前实验无法合理区分关键假设。**

两种停止方式：

```text
Evidence changes or preserves decision
→ Stop

Experiment cannot discriminate
→ Stop current experiment
→ Redesign if still worth testing
```

不得为了得到“更漂亮的数据”无限扩大实验。

---

## 21. 输出

默认输出保持简洁：

```text
【决策问题】

【竞争假设】

【关键未知】

【区分性证据】

【Decision Threshold】

【最小决策充分实验】

【Reality Fit】

【结果】

【解释】

【Verdict】
Supports Focal / Supports Rival / Conditional / Non-discriminating

【决策 / 下一步】
```

不默认输出完整实验流水账。

---

## 22. 硬约束

正式冻结：

1. **实验必须服务于明确决策。**
2. **实验前必须明确竞争假设。**
3. **必须识别真正具有区分力的证据。**
4. **Minimum 指决策充分性最小，不是绝对成本最小。**
5. **Minimum ≠ Toy。**
6. **实验必须保留可能改变决策的关键现实条件。**
7. **必须进行 Reality Fit Test。**
8. **优先隔离主要变量，但不得破坏真实关键交互。**
9. **允许验证 Composite Hypothesis。**
10. **发现差异不等于差异足以改变决策。**
11. **Decision Threshold 不得由 Agent 随意编造。**
12. **技术可行性 Demo 不等于产品决策实证。**
13. **Non-discriminating 不等于两个方案等价。**
14. **实验无法区分时，应停止当前实验而不是继续强行解释。**
15. **不得为了得到预期结果而在实验中途修改评价标准。**
16. **外部证据不能替代本地真实实证。**
17. **最小实证不能为了省成本牺牲 Decision-Relevant Reality。**

---

## 23. 典型误用

### 误用一：做最小 Demo

错误：

> 只证明技术能运行。

正确：

> 证明结果是否足以改变当前产品或架构决策。

---

### 误用二：样本越小越“最小”

错误：

```text
真实目标规模百万级
↓
只测 1000 条数据
```

如果规模会影响结论，则实验不具备 Reality Fit。

---

### 误用三：强制单变量

错误：

> 即使真实系统效果来自变量交互，也强制一次只改一个因素。

正确：

> 能隔离则隔离；必要交互不可破坏。

---

### 误用四：看到差异就选赢家

错误：

> 方案 B 快一点，所以采用 B。

正确：

> 判断收益是否达到真实 Decision Threshold。

---

### 误用五：Agent 自己设阈值

错误：

> “快 20% 就值得迁移。”

除非 20% 有真实业务或产品依据。

---

### 误用六：实验没区分出来就说一样

正确 Verdict：

> `Non-discriminating`

然后判断是否需要重新设计实验。

---

## 24. 已验证场景

当前方法已通过三类不同实际实验设计验证。

---

### 24.1 Graph DB vs PostgreSQL

决策：

> 是否值得为 Agent Memory 引入 Graph DB？

最小决策充分实验：

```text
代表性 Memory 数据集
+
真实 Query Set
+
两个最小实现
+
统一条件
```

必须保留：

```text
Scale
Relationship Density
Traversal Pattern
Latency
Operational Cost
```

验证：

> 基础设施选型可以通过最小但真实的 Workload 实验判断，而不需要先建设完整平台。

---

### 24.2 Agent Runtime Checkpoint

决策：

> 某类长任务是否值得从 Restartable 升级为 Resumable？

必须比较：

```text
Restart Cost
vs
Checkpoint + Recovery Cost
```

同时保留：

- 真实 Intermediate State；
- 代表性 Failure Point；
- 恢复正确性；
- 必要 Effect Safety；
- 实现复杂度。

验证：

> 最小实证验证的是“能力是否值得产品化”，而不仅是“技术能不能做”。

---

### 24.3 Context / Prompt Cache Optimization

决策：

> 稳定前缀 + 按需 Context 注入是否真的降低成本，同时保持任务质量？

由于：

```text
Context Construction
×
Prompt Prefix
×
Cache Hit
×
Task Quality
```

存在真实交互，因此使用：

```text
Baseline Strategy
vs
Candidate Strategy
```

验证组合假设。

观测：

```text
Token Usage
Cache Hit
Latency
Task Success
Error Rate
必要信息遗漏率
```

验证：

> 复杂系统允许使用 Strategy-level Composite Hypothesis，不应为了形式上的单变量实验破坏真实机制。

---

## 25. 重新打开条件

只有出现以下情况才重新打开本阶段：

1. Minimum Decision-Sufficient Experiment 无法形成稳定判断标准；
2. Reality Fit Test 无法防止 Toy Experiment；
3. Decision Threshold 在实际使用中频繁无法定义；
4. Composite Hypothesis 导致实验结果长期无法解释；
5. 方法频繁把 Non-discriminating 误判成方案等价；
6. 实验规模经常失控，无法保持“最小”；
7. 方法系统性导致为了实验而提前建设完整产品；
8. 与外部证据校核或其他分析法产生不可消解的职责冲突；
9. 新实证显示当前协议无法稳定支持真实决策。

---

## 26. 阶段冻结结论

最小实证正式冻结为：

```text
Define Decision
↓
Form Competing Hypotheses
↓
Identify Discriminating Evidence
↓
Define Decision Threshold
↓
Design Minimum Decision-Sufficient Experiment
↓
Reality Fit Test
↓
Run
↓
Interpret
↓
Decide / Redesign
```

合法 Verdict：

```text
Supports Focal
Supports Rival
Conditional
Non-discriminating
```

核心判断：

> **最小实证不是寻找成本最低的实验，而是寻找满足当前决策所需真实性与区分力的最小实验。**

核心纪律：

> **实验的终点不是证明方案能工作，而是获得足以改变或维持当前决策的真实证据。**
