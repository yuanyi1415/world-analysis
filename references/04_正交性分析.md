# 世界分析法阶段冻结04｜正交性分析 v1.0

> **状态：阶段冻结**  
> **所属 Skill：** 世界分析法（world-analysis）  
> **作用：** 作为后续世界分析法 Skill 的正式设计事实源之一。

---

## 1. 定义

> **正交性分析：识别模型中不同分类、属性或状态实际回答的语义问题，判断这些问题是否具有独立定义与有意义的独立变化能力，并确认它们之间的依赖可以通过关系或约束表达；若拆分能够降低隐含耦合或组合复杂度，则重构为独立可组合维度。**

它回答的核心问题是：

> **这些东西真的是同一维度上的不同取值，还是其实属于不同的语义问题？**

---

## 2. 适用场景

优先用于：

- 分类体系；
- 状态模型；
- 等级模型；
- 权限模型；
- 风险模型；
- Capability / Effect / Authority 等多维判断；
- 出现大量组合型枚举时；
- 一个对象经常同时属于多个分类时；
- 新增分类值会频繁影响其他值时；
- 怀疑模型把不同语义维度混在一起时；
- 对抗性约简发现潜在 `Decoupling Split` 时。

典型危险信号：

```text
C0 / C1 / C2 / C3 持续增加

Type A
Type B
Type C
但一个对象经常同时属于 A 和 B

一个状态同时表达：
生命周期阶段 + 风险 + 权限 + 可恢复性
```

---

## 3. 最小输入

```text
Analysis Target
要检查什么模型？

Current Dimensions / Categories
当前有哪些分类、状态或等级？

Required Semantics
模型必须区分哪些真实语义？

Variation Evidence
这些语义在真实场景中如何变化？

Known Constraints
这些维度之间有哪些已知依赖或组合限制？
```

---

## 4. 核心流程

正交性分析正式冻结为：

```text
Identify Semantic Questions
↓
Orthogonality Test
├─ Question Test
├─ Variation Test
└─ Constraint Test
↓
Value Test
↓
Keep / Recompose
```

---

## 5. Identify Semantic Questions｜识别语义问题

对当前每个分类值、属性或状态问：

> **它到底在回答什么核心问题？**

例如：

```text
Resume
→ 工作失败后是否继续原工作？

Effect Safety
→ 外部副作用是否必须避免重复或结果不确定？
```

如果两个值回答的是不同问题，则存在潜在正交性。

原则：

> **先识别语义问题，再分析变量关系。**

---

## 6. Orthogonality Test｜正交性测试

正交性不能只靠“能够独立变化”判断。

正式使用三个测试：

---

### 6.1 Question Test｜语义问题测试

问：

> **两个候选维度是否回答不同且当前模型必须表达的核心问题？**

如果只是两个无关属性，即使可以独立变化，也不能因此成为当前模型的正交维度。

例如：

```text
用户年龄
用户身高
```

两者虽然可以独立变化，但如果分析目标是：

```text
订单支付状态
```

则它们与当前模型无关。

因此：

> **Semantic Distinction 是正交性的必要条件。**

---

### 6.2 Variation Test｜有意义的独立变化测试

问：

> **是否存在与当前问题相关的真实场景，使 X 变化而 Y 保持不变？**

以及反向：

> **是否存在 Y 变化而 X 保持不变？**

如果存在有意义的双向独立变化，则强烈支持：

> 两者不是同一个单轴分类。

注意：

> **Independent Variation 是强证据，但不是单独充分条件。**

---

### 6.3 Constraint Test｜约束表达测试

问：

> **两个维度之间即使存在依赖，是否仍可以通过关系、规则或 Constraint 清晰表达，而不需要重新合并成一个维度？**

例如：

```text
Risk ↑
→ required Authority ↑
```

Risk 与 Authority 存在策略依赖。

但它们回答：

```text
Risk
→ 做错了会怎样？

Authority
→ 谁可以做？
```

因此仍可以保持语义正交。

正式冻结：

```text
Semantic Orthogonality
≠ Statistical Independence
≠ Causal Independence
≠ No Runtime Dependency
```

正交判断的是：

> **语义是否可以独立定义。**

不是：

> **运行时是否完全互不影响。**

---

## 7. Value Test｜拆分价值测试

即使两个维度可以被逻辑拆分，也不代表应该重构。

只有拆分后至少产生以下一种真实收益，才值得重构：

- 降低隐含耦合；
- 减少组合型枚举；
- 减少特殊规则；
- 提高解释力；
- 允许维度独立演化；
- 使约束关系更加显式。

如果拆分后只是：

> 增加更多变量和状态组合

而没有真实结构收益，则保持当前模型。

原则：

> **可拆分不等于值得拆分。**

---

## 8. 正交维度不要求完整笛卡尔积

如果模型被表达为：

```text
Dimension A
×
Dimension B
```

不意味着：

> 所有 A × B 组合都必须合法存在。

可以存在：

```text
Dimension A
×
Dimension B
↓
Constraints
↓
Valid Combinations
```

例如某些权限与认证状态组合可以被规则禁止。

因此：

> **正交意味着可以分别定义，不意味着所有组合都必须允许。**

---

## 9. Recompose｜重新组合

当正交性成立且 Value Test 通过后：

```text
混合分类 / 等级
↓
独立语义维度
↓
显式关系 / Constraint
↓
组合模型
```

目标不是增加更多结构，而是：

> **把原来隐藏在单一枚举或分类中的独立语义显式化。**

例如：

```text
Continuity Level C0 / C1 / C2
```

如果实际混合：

```text
Resume Contract
×
Effect Safety
```

则应重构为两个独立维度。

---

## 10. 什么时候不应该拆

以下情况通常不应拆分：

```text
回答的是同一个核心语义问题
+
缺少有意义的独立变化
+
拆分后无法降低耦合
+
需要增加大量约束才能维持原有语义
```

例如：

```text
Turn lifecycle
active / completed / interrupted / failed
```

虽然理论上可以人为拆成：

```text
Activity State
×
Outcome State
```

但如果拆分后：

- 大量组合没有稳定意义；
- 需要更多合法性约束；
- 没有降低真实耦合；
- 没有提高解释力；

则不应拆。

---

## 11. 与对抗性约简的边界

两者关系：

```text
对抗性约简
→ 发现某个结构可能存在隐含耦合
→ 提出 Decoupling Split 候选
```

```text
正交性分析
→ 专门验证：
这些语义是否真的应该独立
以及应该怎样重新组合
```

因此：

> **对抗性约简负责发现 Split 候选，正交性分析负责证明 Split 是否成立。**

---

## 12. 与第一性约简的边界

第一性约简：

```text
→ 从现实问题寻找最小有效语义
```

正交性分析：

```text
→ 检查这些语义在模型中是否被错误混维
```

因此正交性分析不负责重新追问整个问题的第一性基础。

---

## 13. 停止条件

正式停止条件：

> **每个保留维度已经回答一个稳定且必要的核心语义问题；不同维度之间的依赖能够通过显式关系或 Constraint 表达；继续拆分已经不能降低耦合、提高解释力或减少组合复杂度。**

可简化为：

```text
每个轴回答一个核心问题
+
存在有意义的独立变化
+
依赖可通过显式约束表达
+
继续拆分无新增结构价值
```

## 15. 硬约束

正式冻结：

1. **正交性分析判断的是语义维度，不是物理变量。**
2. **独立变化是强证据，但不是充分条件。**
3. **候选维度必须回答不同且当前模型真正需要表达的核心问题。**
4. **正交不等于统计独立。**
5. **正交不等于因果独立。**
6. **正交不等于运行时完全无依赖。**
7. **存在 Policy / Constraint 依赖，不自动破坏语义正交性。**
8. **正交维度不要求所有组合形成完整笛卡尔积。**
9. **可逻辑拆分，不等于应该拆分。**
10. **拆分必须产生真实结构价值。**
11. **如果拆分后需要更多无意义状态与约束，应保持原模型。**
12. **正交性分析不能为了形式美制造更多维度。**
13. **正交性分析不能取代第一性约简或对抗性约简。**
14. **重构后的模型仍需接受其他分析法与真实实证验证。**

## 16. 典型误用

### 误用一：只要能独立变化就认为正交

错误：

```text
年龄和身高能独立变化
→ 必须作为当前模型两个轴
```

正确：

> 还必须确认它们是否都是当前问题需要表达的不同语义。

---

### 误用二：存在依赖就重新合并

错误：

```text
Risk 会影响 Authority
→ Risk 和 Authority 是同一维度
```

正确：

> 依赖可以通过 Policy / Constraint 表达，只要语义仍可独立定义。

---

### 误用三：强求完整组合

错误：

> 两个正交轴必须允许所有组合出现。

正确：

> 正交模型可以拥有组合约束。

---

### 误用四：无限拆分

错误：

> 只要一个状态可以写成两个变量，就应该拆。

正确：

> 只有拆分能够降低耦合或提高解释力时才有价值。

---

## 17. 已验证场景

当前方法已通过四类不同模型验证：

### Resume × Effect Safety

结论：

> 应拆分并保持正交。

验证：

- 回答不同语义问题；
- 存在真实独立变化；
- 组合可自然表达；
- 拆分降低隐含耦合。

---

### Risk × Authority

结论：

> 应保持语义正交。

验证：

> 存在策略依赖并不等于不正交。

---

### Turn Lifecycle

候选：

```text
active / completed / interrupted / failed
```

尝试拆成：

```text
Activity × Outcome
```

结论：

> 不应拆分。

原因：

- 拆分没有降低耦合；
- 大量组合缺少稳定语义；
- 需要增加额外约束。

验证：

> 可逻辑拆分不等于值得拆分。

---

### Truth / Record / Work

结论：

> 当前结构已经正确表达为可叠加的独立 Commitment Purposes，无需继续拆分。

验证：

> 正交性分析不仅能发现混维，也能确认现有模型已经足够正交。

---

## 18. 重新打开条件

只有出现以下情况才重新打开本阶段：

1. Question / Variation / Constraint 三个测试无法覆盖重要混维问题；
2. Value Test 无法稳定判断拆分收益；
3. 实际使用中频繁把普通相关变量误判为正交维度；
4. 实际使用中频繁因存在依赖而错误合并独立维度；
5. 与对抗性约简的 Decoupling Split 出现不可消解的职责冲突；
6. 新实证发现当前模型无法处理重要组合约束；
7. 方法系统性导致分类维度数量膨胀。

---

## 19. 阶段冻结结论

正交性分析正式冻结为：

```text
Identify Semantic Questions
↓
Orthogonality Test
├─ Question Test
├─ Variation Test
└─ Constraint Test
↓
Value Test
↓
Keep / Recompose
```

核心判断：

> **正交是语义可以独立定义，而不是彼此完全没有关系。**

拆分条件：

> **既存在不同核心语义和有意义的独立变化，又能够通过显式约束表达依赖，并且拆分真正降低耦合或提高解释力。**

核心纪律：

> **可拆不等于该拆；有关联不等于同维；正交不等于完整笛卡尔积。**
